# ADR-0003：COW 采用事件驱动最终一致与首次快照优先

- **状态**：Accepted
- **日期**：2026-11-10
- **决策范围**：D-009 / D-010 / D-011 / D-017 / D-018（COW 机制与 Revision）
- **确认人／决策权威**：用户已确认 D-009～D-018 业务裁定；本 ADR 于 2026-11-10 由用户明确批准为 Accepted
- **替代**：无
- **被替代于**：无

## 背景与已确认依据

LightTrackerItem 派生采用 Copy-on-Write：初始不物化完整业务内容（Source-backed）。来源业务对象修改时，需要保护已有派生变体，使其内容脱离来源（Local-backed）。

用户已确认（D-009～D-018）：

- COW 采用异步事件驱动，只保证最终一致（D-010）。
- 来源修改前事实作为事件关联的不可变内容快照传递（D-010）。
- COW 目标集合在事件 Handler 消费时确定，不追溯比较派生完成时间与修改开始时间（D-017）。
- 首次快照优先：物化内容由首次相关来源修改前快照决定（D-011）。
- Revision 显式升级触发 COW（D-018）；事件顺序由事件框架顺序消费兜底（D-018）。

## 决定

- COW 采用异步事件驱动、最终一致；不引入跨聚合全局时序协调机制。
- 来源 BC：修改前取完整业务快照 → 保存 → 发携带不可变快照的事件。
- Handler 消费时查询 `SourceLocalId/SourceRevision` 匹配且未物化的 LightTrackerItem，命中的都物化。
- 物化后 `SourceLocalId=LocalId`、`SourceRevision=Revision`（Local-backed），LocalId/CommonId 不变。
- 首次快照优先，后续事件不覆盖已物化内容；Revision 显式升级同样触发 COW。

## 备选方案与权衡

- **A. 同步/强一致 COW**：在来源修改事务内同步物化所有派生变体——跨 BC 大事务，违反 Working Set 与业务 BC 的职责边界，且放大延迟。
- **B. 修改开始时固定目标集合**：需跨聚合时序协调（派生完成 vs 修改开始），D-016 曾尝试、D-017 排除，复杂度高。
- **C. 异步事件驱动 + 消费时确定目标（采纳）**：职责清晰、实现简单；代价是最终一致，物化前允许暂时读到修改后内容。

## 后果

- 物化前派生工作集可能暂时读到来源修改后内容（业务已接受）。
- 依赖事件框架顺序消费、幂等去重、不可变快照可靠交付（实施前提，不在本 ADR 定技术方案）。
- 首次快照优先的乱序/幂等实现细节留待实施评审。
