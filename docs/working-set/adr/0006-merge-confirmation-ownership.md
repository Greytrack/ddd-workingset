# ADR-0006：合并确认归属轮次，跨轮次独立查询

- **状态**：Accepted（2026-11-20，用户明确确认按此方案实施）。
- **替代范围**：替代 [ADR-0005](0005-merge-execution-model.md) 与 D-019 关于「Checkpoint 独立聚合」的部分决定。保留
  MergeEntry 归轮次、已有证据要求及业务 BC 和 LightTrackerItem 的独立提交。

**关联**：[执行契约 §6](../domain/merge-execution-contract-v1.md#6-合并确认与跨轮次查询)、[设计图](../diagrams/merge-entry-lifecycle.md)、[SCN-058](../scenarios/core-scenarios.md)。

## 决定

单条确认与产生它的 MergeEntry 同生命周期：成功且要求确认时生成不可变版次证据，不能独立修改或撤销。MergeRound
仓储在同一事务保存条目结果、确认行和轮次状态；确认写失败时轮次不结束。已提交的业务内容由业务回执重投推进，不回滚或重复执行。

跨轮次当前基准是 CQRS 只读结果，从旧表取当前最新行，再判断状态与双侧版次。历史 REVOKED 可读。确认历程继续追加并按条目 ID
幂等；保留 V3 批次和序号语义，不级联清理。

## 取舍

保留独立 Checkpoint
能承载独立修改或撤销，但需要待确认状态、请求、回执及其重投。确认归轮次用一个事务保证结束状态和确认行一致；代价是确认表写失败会阻塞轮次收敛。若恢复用户撤销、允许旧端并行独立写入，或需要确认记录单独治理，应重新评估边界。

## 影响与验收

仓储原子写入、查询先选最新再筛状态。验收应证明：故意拒绝确认写入时轮次保持非终态；重投已提交的 BC 回执能完成且不重复修改业务对象；B
完成后重放 A，不新增历史或改写 B。
