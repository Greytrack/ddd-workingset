# ADR-0010：工作集创建与扩展按 Tracker 基线时间尽力派生

- **状态**：Accepted
- **日期**：2026-11-21
- **确认依据**：团队裁定无需冻结父 Item 清单，用户授权实施。
- **替代范围**：[T7-D](../implementation/t7-d-index-verification.md) 的受理时冻结、沿冻结清单继续及对应存储。

## 决定

创建和扩展任务在 `working_set_creations.result` 保存选择、各 Tracker 的基线时间与游标进度。历史时间由请求指定；缺省 HEAD
统一使用首次受理时间，与 Item 创建时间使用同一数据库时钟。共享 Tracker 仍复用权威对象；基线时间只参与非共享 Item 的候选查询。

执行按父 Tracker、基线时间与 LocalId 游标分页。首版 ALM 和 LTI
以持久化的创建时间约束当前可读、未软删候选，时间上界包含等值。缺少可信创建时间的行不纳入；候选与内容可随父端状态变化。历史时间用于约束候选范围，业务字段与
Revision 来自执行时可用的数据。

已派生 LTI 继续保存有效来源和来源版次。保留 COW、来源行锁、软删与永久删除守卫、家族认领和已提交游标。关系及附件的既有派生基准约定继续适用。

## 权衡与切换

保留受理时清单可以稳定重放且留存所有被删除候选的明细，但增加受理扫描、存储和业务 BC
耦合。执行时按指定时间分页符合并行产品线的容差，重投沿用时间与已提交游标，不能保证候选列表一致。

保留数据的环境在切换前排空依赖快照的未终态任务。新库省去旧任务快照表；已有库可在确认无依赖后独立移除。已有数据的创建时间只从可信来源补录，开发或
Demo 可通过空库重建取得初始证据。

验收覆盖按 Tracker 保存不同基线、HEAD
重放、时间上界、逐项部分成功和已有家族幂等。入口见 [T7 契约](../domain/working-set-creation-lro-design.md)。
