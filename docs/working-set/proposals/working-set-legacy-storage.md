# Working Set 旧表存储迁移方案

**Status: Draft**

本方案基于 [当前设计基线](../BASELINE.md) 与 [ADR-0004](../adr/0004-productspace-independent-aggregate.md)。Working Set
聚合根改用旧表 `air_inst_workingset`，保留工作集身份、不可变父级、默认工作集保护、创建任务可见性以及绑定语义。现行映射见 [
`schema.sql`](../../../deploys/src/main/resources/schema.sql)。新库初始化和应用读写已按确认映射接入；存量库切换待单独对账和演练。

| 项目         | 推荐做法 / 待核实事实                                                                                                                                                                                                              |
|--------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 根身份       | 用户确认 `id = instance_id = common_id = localId = workingset_id`，依赖表外键指向旧表 `id`。                                                                                                                                       |
| 父子与默认根 | 默认根 ID 为 `1`，颜色为 `#FFFF`；`parent_id` 指向派生链的直属父级，`workingset_id` 存自身 ID。新库的默认根写入空父级，兼容读取旧数据中的 `0`。                                                                                    |
| 空间与归属   | V4 一个 Working Set 可有多个 ProductSpace 绑定，不能从任意一个绑定推断根行的 `work_space`。确认旧系统的空间列究竟是隔离键、单一归属或可空，以及全局默认根如何写入。                                                                |
| 必填字段     | 用户确认自举分类 `1008/100801/10080101`、自举 Tracker `584190236948832`、单版次 `revision=1`、`version_type=10001`。新工作集编号暂用 `WS-<id>`；新行所有者和审计使用请求用户或任务已保存的提交者。旧客户端省略颜色时使用 `#FFFF`。 |
| 删除         | 确认 V4 删除在旧表应硬删还是标删。标删时，普通读取和谱系必须过滤已删；入境引用仍须检查活动状态，外键只能保证物理行存在。父级、绑定和默认根的现有禁止条件保持不变。                                                                 |

**推荐方案：直接切换聚合根表。** 对账完成后，JDBC 命令仓储和 MyBatis 读侧都改读写旧表，绑定仍在 `space_bindings` /
`tracker_bindings`，创建任务按各 Tracker
的基线时间派生，不再保存受理时冻结清单（[ADR-0010](../adr/0010-working-set-creation-tracker-baseline-time.md)）。已有
Tracker、空间绑定、Requirement 等引用同步迁移。取数保留普通视图与任务内部视图区分，尤其是
Pending/Running 期间的隐藏、重放及祖先防环。

**备选方案：过渡期增加只读兼容视图。** 若依赖方必须暂时保留旧 V4
列名，可由旧表生成只读别名，逐批替换查询；物理外键仍必须指向具有唯一键的实体表。视图可以缩小一次切换的查询改动，但不能作为第二写入口，也不能解决身份和版本歧义。本仓库可同时更新两侧，优先直接切换。

1. 旧表对账与回填属于一次性存量迁移，不在当前空库 schema 中保留脚本；迁移必须在隔离副本上比对根
   ID、父节点、循环和断链、已删可见性、同身份多行、绑定和任务悬挂引用，并记录旧系统是否继续写入及写入职责。
2. 先验证一条纵向链路：默认根读取 → 新建子工作集 → 两侧查询正确 → 已有 Tracker/绑定可引用。再接入后台创建、祖先/子级读取、删除，并逐一替换外键、Demo
   和测试夹具。
3. 演练停写、保持 ID 回填、引用约束验证和回退。已有数据库用显式迁移，启动不自动重置或回填。验收覆盖默认根不可删除、父级不可变、创建中隐藏、任务重放、共享绑定与派生流程，以及删除前置条件。
