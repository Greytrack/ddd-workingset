# V4 工作集本体设计

> 2026-11-05 · 新架构设计稿，尚未实现。

工作集定义使用哪些 Tracker；Tracker 表达记录的版本线；同一记录通过 CommonId 关联派生变体，通过 LocalId 区分当前实例。业务调用方使用完整业务对象，Shared Kernel 在内部处理来源读取、实例化和写入保护。

默认工作集由平台元数据预置，ID 固定为 1，不可删除、不可隐藏。Tracker 只能通过默认工作集的对外入口创建，再从直接父工作集逐层纳入子工作集；共享复用绑定，非共享派生副本。新请求重复纳入报错，非共享副本删除完成后可重新派生新副本。

WorkingSet 显式持有产品空间绑定，每个空间绑定组织零到多个 Tracker绑定；移除全部Tracker后空间仍保留。两层绑定属于WorkingSet聚合，ProductSpace与Tracker仍为独立聚合。

TrackerItem 是对外公开的接口协议；LightTrackerItem 是 SK 内部私有独立聚合。业务对象不持有索引，生命周期通过事件同步。本阶段不使用代理。

默认工作集初始无产品空间、无 Tracker。三层分类元模型由独立共享内核预置并提供约束；用户创建产品空间后，通过事件逐分类建立持久化 Tracker 投影。共享 Tracker 及其条目在默认工作集维护生命周期，非共享对象在各自所属工作集维护。

## V4 规约

采用 [domain-driven-design skill](../../../../.agents/skills/domain-driven-design/SKILL.md) 的战术规则：按身份区分实体和值对象，按不变量划分聚合，实体封装合法转换，跨实例规则交给领域服务，应用层负责流程，Repository 按聚合组织。

仓库 Lattice 的现行 overlay 面向 Backend 2.1。本目录依据本轮 V4 设计授权，不继承 DataObject、Long 主键、Biz/SDK/SDKImpl 或允许任意跨聚合事务的实现约束；不修改该全仓库配置。领域身份可以使用具名值类型，持久化编码由实现选择。

| 层次 | 负责 | 不负责 |
|------|------|--------|
| 领域 | 身份、不变量、合法转换、纯计算规则与事实事件 | 数据库、消息中间件、事务注解 |
| 应用 | 加载、授权上下文、调用行为、流程与事务边界 | 直接设置状态绕过领域行为 |
| 基础设施 | 仓储实现、历史存储、类型内容端口、可靠事件 | 决定业务状态是否合法 |
| 接口 | 请求转换、输入校验、呈现 | 重复建立领域规则 |

## 本稿采用的建模决策

1. WorkingSet、Tracker、具体业务对象、LightTrackerItem 与引用关联各自为独立聚合。
2. TrackerItem 继承 BusinessObject，业务类型实现该公共协议；不暴露索引模型或仓储。
3. LightTrackerItem 通过目标 LocalId 对应条目；稳定状态一条目一索引，事件传播期间允许暂时缺失或滞后。
4. 业务新增、删除、恢复和实例化通过可靠事件驱动索引更新，不跨聚合事务。
5. 异步实例化转换已有逻辑条目的存储承载，不重新创建目标身份；查询通过固定内容重建对象。
6. 内容与索引不再同事务保存。查询、乱序事件和删除窗口的约束见 [03](./03-consistency.md)。

## 不在本稿展开

不定义分类/属性规则体系、业务工作流、比对合并内部对象、具体存储表及版本迁移。业务模型自行维护其内容规则；实例化时必须调用其内容契约，不能绕过这些规则。创建、扩展、替换与删除工作集对引用的影响由专项协议处理。
