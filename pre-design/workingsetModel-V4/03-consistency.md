# 一致性、风险与验收

> 2026-11-06 · 无跨聚合事务；业务内容与私有索引通过事件最终一致。

## 1. 事务边界

| 事务 | 允许写入 |
|---|---|
| 业务命令 | 一个业务聚合及其事件登记 |
| 索引同步 | 一个 LightTrackerItem 及其消费凭据、必要事件登记 |
| 实例化 | 一个目标业务聚合及完成事件；索引另行确认 |
| 创建 LRT | WorkingSet、Tracker、索引、关系分别提交，见 [05](./05-workingset-creation-lrt.md) |
| 内容替换 LRT | 准备资源逐聚合提交；单 WorkingSet 事务切换 contentRevision；旧范围清理异步进行，见 [06](./06-workingset-content-replacement.md) |

不得在 Handler 外层开启覆盖业务内容和索引的总事务。相同 LocalId 不意味着相同事务边界。

## 2. 异步窗口的查询与命令

1. **原生创建已提交、索引未到达**：创建接口返回业务提交成功；工作集列表允许短暂未收录，明确同步中。若要求立即出现在列表，必须增加等待同步或读模型补偿，不能宣称现有事件方案天然满足。
2. **本地内容已提交、索引仍为 VIRTUAL**：查询解析先核对目标本地权威内容及提交凭据，有则使用本地内容；无则读取固定 source。不得继续显示旧 source 覆盖用户修改。
3. **业务已删除、索引滞后**：业务权威生命周期过滤已删除对象；物理删除凭据阻止回源重建。不能把本地行缺失直接解释为 VIRTUAL。
4. **虚拟对象写入**：幂等准备目标本地内容、验证业务版本后编辑或删除。并发实例化和用户编辑由目标身份唯一性与业务版本控制，落后事件不得覆盖结果。
5. **来源更新**：只能使用匹配切点的历史或保留事件输入；不可读时返回处理中或可重试错误，禁止读取源最新值作为替代。

这些规则需要可查询的本地提交、生命周期和删除证据。仅有事件框架持久化并不代表该查询能力已经存在；接入实现前必须落实查询端口与保留期限。

## 3. 事件顺序与恢复

- eventId 去重，目标聚合版本控制先后；时间戳不是顺序依据。
- 先收到删除后收到创建，不得重建活动索引；保留最终处理版本和删除凭据，即使索引已物理清除。
- 索引不存在时不能一概丢弃修改事件：暂存等待创建事实，或从权威生命周期重建，再按版本应用。
- 生命周期可用完整较新状态收敛；COW 的旧内容事件不能仅因版本较旧丢弃，仍可能服务尚未实例化的派生目标。
- 原生创建事件建立索引；派生实例化完成只确认既有目标，不发布新的业务创建事实，不分配新身份。
- 任务保留覆盖尚未生成的索引，完成时转换为持续历史保留；delete2 不可提前抹除仍被依赖的旧内容。

## 4. 聚合划分的代价与约束

LightTrackerItem 独立聚合合理地承载共享内核内部的身份解析与来源生命周期，业务对象不再依赖其结构。代价是原先内容和索引的强一致变成跨聚合协议，必须支持中间态、重试和对账。

稳定状态每个受管条目对应唯一索引；原生创建短暂缺索引、删除后短暂残留是同步窗口。派生索引没有本地内容是合法存储形态，不是同步故障。不可根据这两个现象统一做孤儿清理。

## 5. 验收与待落实

- 默认工作集从平台初始化数据加载，ID=1；删除和隐藏均拒绝，启动时不创建第二个默认根。
- 普通 Tracker 创建仅在默认工作集允许；子工作集只能从直接父工作集纳入，跨级选择拒绝。
- 同请求重试返回原结果，新请求重复纳入报错；并发选择覆盖准备占用与有效绑定。
- 非共享副本删除完成才释放重新纳入资格；新副本使用新身份，迟到旧事件不修改新副本。

- 重复、乱序事件及进程重启不产生重复身份、不复活删除条目。
- 新增、编辑、delete、undelete、delete2 都有完整事件出口；普通 Part 不建索引。
- 索引确认失败后，本地新内容仍正确可读，重试不覆盖后续编辑。
- 固定 snapshot 的内容可恢复，创建期间持续源变更不破坏派生语义。
- 并发实例化、删除与用户写入均有版本守卫。
- 事件遗漏可被对账发现并重放；索引仓储不向外公开。
- 明确列表同步延迟目标、删除凭据保留周期、事件查询能力及失败告警责任。
- 工作集 READY 依赖创建清单完成，不以任务进度投影或全部内容实例化为依据。

拓展发布与旧关系恢复分别提交：发布后允许显示关系恢复中；用户已删改关系不能被迟到恢复覆盖。未建行关联必须有原关系意图及切点证据，详见 [05 §10](./05-workingset-creation-lrt.md#10-拓展工作集增量纳入与关系恢复)。

实例化事件链路及专项验收统一见 [07](./07-item-instantiation-events.md)。框架负责可靠交互；本文及领域设计仅约束业务输入、独立聚合提交、事件事实和最终状态，不规定多阶段事务、Outbox 或 Saga 的实现。

新增验收：同工作集 CommonId 冲突拒绝；同族跨工作集 LocalId 不重复；SHARED 解绑不删共享内容；UNSHARED 非空或有派生子级拒绝删除；HEAD 使用提交时刻，指定 snapshot 使用其时间戳，单版次历史读取不退回当前值。

产品空间创建、每个分类投影 Tracker、默认工作集绑定、空间初始化完成分别提交。验收空间内分类唯一、跨空间相同分类合法、重复事件不重复投影、共享生命周期归默认根、非共享归目标工作集；完整协议见 [09](./09-product-space-classification-projection.md)。

空间绑定与Tracker绑定同属WorkingSet聚合，其匹配关系、有效范围与显式移出守卫可在单工作集事务内维护；ProductSpace、Tracker各自仍独立提交。验收最后一个Tracker移出后空间保留、同工作集空间绑定唯一、跨空间Tracker绑定被拒绝、空空间snapshot及替换不丢失。
