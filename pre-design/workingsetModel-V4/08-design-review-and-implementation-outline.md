# V4 工作集设计审查与详细设计大纲

## 1. 总体结论

**核心领域边界与主要用例已具备详细设计基础；实现前需要补齐状态转换、接口合同、并发守卫和基础能力接入。**

审查范围包括工作集本体、引用关联和比对合并。采用 Lattice 战术建模规则：聚合维护自身不变量，跨聚合按身份关联，应用层编排，每次事务只修改一个聚合，通过异步事件最终一致。事件框架负责可靠交互，领域设计不展开框架事务实现。

| 维度 | 结论 | 详细设计重点 |
|---|---|---|
| 功能 | 默认根预置、逐层纳入及创建、拓展、替换、实例化等主流程明确 | 解绑、删除恢复、快照释放、重挂的完整状态与接口 |
| 聚合 | WorkingSet、Tracker、LightTrackerItem、业务对象、关系及合并基准边界明确 | 状态机、守卫、字段、创建与重建、仓储合同 |
| 接入 | TrackerItem 公开，LightTrackerItem 私有，业务类型独立 | 类型注册、批量内容读取、工厂重建、业务写入及事件适配 |
| 一致性 | 业务内容、索引、关系、Round、Checkpoint 分别提交 | 因果顺序、部分成功、确认处理中、取消与迟到事件 |
| 基础能力 | 固定历史、删除证据、版本映射、写入准入是必要依赖 | 明确提供方、调用合同、保留期限及失败结果 |

## 2. 核心设计约束

### 2.1 身份与成员

三层分类元模型是独立共享内核，启动前预置并提供属性、规则约束。默认工作集初始没有产品空间或 Tracker；产品空间是独立聚合，在默认工作集维护，创建事件驱动全部分类逐项投影为 Tracker。参见 [产品空间与分类投影](./09-product-space-classification-projection.md)。


1. 一个工作集的有效内容范围内 CommonId 唯一，使用 WorkingSetId 与 CommonId 定位逻辑条目。
2. LocalId 全局唯一；跨工作集的派生业务对象可以持有相同 CommonId，但具有不同 LocalId。
3. SHARED 多工作集绑定复用同一个对象，不生成新的业务身份。
4. 派生创建即确定目标身份、归属及固定内容依据；查询重建与实例化均不重新分配身份。
5. 同一工作集有效范围内，同一产品空间、分类只有一个 Tracker；不同产品空间可有相同分类的独立投影。
6. WorkingSet 显式持有空间绑定，空间绑定组织 Tracker绑定；移除全部 Tracker 后空间仍存在于本工作集，ProductSpace 本体不复制。
7. contentRevision 表达工作集有效内容范围，不是业务版次或聚合并发版本。

### 2.2 快照与业务版次

| 选择 | 切点 | 读取规则 |
|---|---|---|
| HEAD | 用户提交请求时固定的时间戳，无 snapshotId | 各实例在该时刻的最新适用版次 |
| 指定 snapshot | 根据 snapshotId 获取固定时间戳 | 各实例不晚于该时刻的最大适用版次 |

所有业务对象至少有版次 1。多版次对象修改升版次；单版次对象始终只有版次 1，但仍需读取其在指定切点的内容。版次号、内容并发版本和历史时间依据分别维护。

快照先确定成员存在性和生命周期，再逐实例选版次。历史不可读时明确失败或等待，不回退到当前内容。普通工作集中的 SHARED 数据保持共享语义，不因内容替换而回写历史值。

### 2.3 聚合与事件

- TrackerItem 是 SK 对外接口，具体业务聚合实现它；业务对象不持有 LightTrackerItem。
- LightTrackerItem 是 SK 私有独立聚合，通过事件维护来源、实例化标记和生命周期摘要。
- 虚拟条目是已存在的逻辑聚合；实例化只转换存储承载。业务写事件保护全部受影响的虚拟派生条目，完成事件独立确认索引。
- MergeRound 管理本轮进度和唯一终态 ApplyResult；MergeCheckpoint 跨轮次独立保存最近处理状态。
- 已提交业务不能因后续索引、关系或确认处理失败被描述为已回滚；查询分别展示应用结果和处理进度。

### 2.4 Tracker 与工作集生命周期

- 默认工作集通过平台元数据初始化预置，ID=1；不可删除、不可隐藏，不走运行时创建流程。创建子工作集前，全部业务数据均在默认工作集内。
- REST 触发的 Tracker 创建只允许在默认工作集，子工作集只能从直接父工作集逐层纳入。共享建立绑定，非共享派生新副本，不能跨级纳入。
- 一个 Tracker 在同一工作集不可重复纳入。相同请求重试幂等，新请求重复纳入报错；准备中的纳入同样占用该选择。
- 非共享派生副本删除完成后允许重新纳入，生成新的 TrackerId 和条目 LocalId；不复活旧副本。
- 有相关 TrackerItem 的 Tracker 不可物理删除；VIRTUAL 和尚未彻底清除的软删除条目都计入非空。
- SHARED Tracker 及其条目在默认工作集维护生命周期，UNSHARED 在所属工作集维护；SHARED 从子工作集移除只解除 Binding，不删除共享数据、索引或关系。
- UNSHARED 销毁必须为空且没有派生子级；空 Tracker 可以移除，实际清理仍须满足历史保留条件。
- 历史内容替换保留目标工作集身份及父级，直接派生链重置到直接父工作集；历史版本只提供恢复内容。
- 恢复内容在目标建立后 source 指向自身；直接父项缺失时阻止发布，不跨代指向或补造历史对象。

## 4. 聚合详细设计责任

| 模型 | 边界 | 必须形成的规格 |
|---|---|---|
| ProductSpace | 默认工作集维护的独立根 | 创建与初始化完成、状态、事件、空间使用资格及生命周期 |
| 分类元模型 | 外部共享内核，不展开内部模型 | 分类身份集合、属性规则约束及演进接入契约 |
| WorkingSet | 聚合根，管理选择、范围与发布 | 状态、范围版本、默认根／叶子守卫、发布／取消、删除恢复 |
| WorkingSetProductSpaceBinding | WorkingSet 内部实体，组织Tracker绑定 | 空间纳入、空集合、显式移出、有效范围与历史 |
| WorkingSetTrackerBinding | 同一WorkingSet内、归属于空间绑定的实体 | 身份、空间匹配、有效范围、状态与visible、解绑、历史 |
| Tracker | 聚合根，管理容器与派生元信息 | 共享属性、目录与来源、创建／派生、归档／删除、可写许可 |
| LightTrackerItem | 私有聚合根 | 身份、直接父级、内容来源、两种状态维度、事件版本、实例化确认 |
| TrackerItem | 公共接口协议 | 最小能力、身份类型、加载事实与写入接入要求 |
| Requirement／Bug | 业务模块聚合根 | 内容不变量、从属实体、创建／重建／实例化入口、业务事件 |
| Snapshot | 聚合根 | 捕获范围、不可变切点、保留依赖、查询与释放 |
| Reference／Association | 各自独立聚合根 | 关系身份、版次、有效性、钉版、修复、传播与删除守卫 |
| MergeRound／ApplyResult | 轮次聚合及其终态值对象 | 冻结请求、进度、在途结果、取消、失败、唯一终态结果 |
| MergeCheckpoint | 跨轮次独立聚合根 | 有向上下文、确认依据、消费顺序、撤销与有效性 |
| WorkingSetProvisioning | 持久化应用流程 | 阶段、输入、映射、回执、进度、失败恢复；不拥有业务聚合 |

每个聚合都应有“字段—不变量—行为—事件—仓储—测试”映射。跨聚合只按身份关联；仓储按聚合装载和保存，查询模型可组合已提交事实。

## 5. 与业务模块的接入合同

按以下职责定义接入合同；接口按能力组织，不要求每项职责单独建立一个类。

| 交互点 | SK 负责 | 业务模块负责 | 必须产出的契约 |
|---|---|---|---|
| 业务语义转译 | 创建／拓展／替换等机制 | GateFlow 草稿资格、ALM 业务流程及权限意图 | 命令参数、上下文、错误与任务结果 |
| 分类元模型接入 | 读取分类集合、保存投影身份、按公开约束建立 Tracker | 分类共享内核团队提供分类及属性／规则合同 | 冻结集合、规则依据、配置变化与缓存可用性 |
| 产品空间创建 | 接收空间事件，逐分类建 Tracker 并完成默认绑定 | 空间应用层创建聚合、维护状态与权限 | ProductSpaceCreated、初始化进度、完成结果与重试键 |
| 生命周期归属 | 解析 owningWorkingSetId，区分共享绑定和非共享所有权 | 按权威工作集校验业务生命周期及权限 | 默认根共享操作、子工作集解绑、后台服务身份 |
| 类型注册 | 根据 itemType 选择能力实现 | 提供受管类型实现，Part 可不接入 | 支持能力、重复注册／缺失实现的启动检查 |
| 查询 | 解析工作集范围、内部索引和来源 | 从固定内容重建具体业务对象 | 批量输入输出、身份覆盖、未找到／已删除／处理中区分 |
| 原生创建 | 接收创建事实建索引 | 分配合法身份、创建内容并发事实 | 事件字段、版本、权限、列表同步窗口 |
| 业务写入 | 保护派生依赖并维护索引 | 当前聚合业务守卫、修改前内容、写事件 | edit/delete/undelete/delete2 的一致出口 |
| 实例化 | 目标身份和来源匹配、逐目标编排 | 完整内容构造、归属重写、本地保存与完成事实 | 输入依据、成功／已有／过期／已删除结果 |
| 引用关联 | 解析成员身份与有效范围 | 关系聚合按自身规则处理 | 端点事实、版次证据、缺失意图与冲突结果 |
| 权限／历史／事件 | 声明所需能力与失败语义 | 对应平台能力提供方实现 | 可查询性、保留期限、服务身份与可靠交付承诺 |

模块依赖方向：业务模块依赖 SK 公共协议；SK 核心不依赖业务实现；业务适配器实现 SK 所需能力，组装层负责注册。LightTrackerItem 与私有仓储不出现在公共签名中。Application Handler 接收事件，聚合行为校验转换；实体方法不访问事件框架。

## 6. 下一步详细设计大纲

详细设计按 D01–D09 组织，文档放入 `workingsetModel/detail/`。每份规格必须包含接口、状态、失败行为和验收条件。

### D01 统一语言、身份与版本

- 整体主图使用强类型 ID 属性，跨聚合连线明确标注“按 ID 关联”；身份值对象图单独展示类型与使用关系，不在主图展开每个 ID 节点。
- WorkingSetId、ProductSpaceId、TrackerId、两类 BindingId、SnapshotId、CommonId、LocalId 不互相替代；目录父级及来源仍复用 TrackerId。分类与项目身份使用其所属模块的公开合同。
- 空间绑定与Tracker绑定分别定义身份；明确同一工作集聚合内的组织关系，避免多种bindingId混用。
- ProductSpaceId、classifyId、owningWorkingSetId、CommonId、LocalId、TrackerId、WorkingSetId、parentLocalId、source 与内容切点的关系。
- 区分产品空间、业务项目、工作集三个维度；分类投影唯一性按有效工作集范围及产品空间判断。
- 默认根 ID=1、仅默认根创建 Tracker、直接父级纳入及重复纳入异常的接口约束。
- contentRevision、业务 revision、业务并发 version、索引 version、事件版本分别定义。
- 创建／派生／实例化／替换／删除的身份变化表；不变项必须可测试。
- 定位参数及唯一性反例，工作集范围与共享多绑定规则。

**完成标准**：同一个术语在所有图、事件和接口中只有一种含义；成员唯一性、内容范围和直接父级的执行规则完整。

### D02 聚合状态与行为合同

- 每个根及内部实体的字段、值对象、空值条件与不可变字段。
- 状态转换表：当前状态、命令、守卫、新状态、领域事实、失败类别。
- 方法只维护自身不变量；外部事实以显式输入传入，不能伪装成事务内强一致保证。
- 工厂、重建、实例化分别定义；Repository 不触发隐式业务创建。
- 跨聚合属性只能保存强类型 ID；内部实体和值对象允许对象字段和集合，不能因使用 ID 而把两层 Binding 拆成独立聚合。

**完成标准**：ProductSpace、WorkingSet、Tracker、索引、Snapshot 的生命周期都有正向和拒绝用例；产品空间聚合不循环创建其他聚合。

### D03 公开 API 与业务类型接入

- TrackerItem／BusinessObject 的最小协议；公共服务的命令、查询和任务接口。
- 分类共享内核适配：读取全部分类及公开约束；Tracker 保存 productSpaceId、classifyId 和生命周期归属。
- 类型能力适配：读取固定内容、批量重建、建立目标本地内容及事件映射。
- Requirement、Bug 两个受管样例与 Part 非受管对照；带从属实体的完整内容样例。
- 失败结果、授权上下文、批量部分失败、输入输出顺序与兼容性政策。

**完成标准**：仅依赖公共模块的业务样例能完成读写，不导入 LightTrackerItem。

### D04 查询与历史内容

- 产品空间列表从显式空间绑定读取，不能从Tracker去重推导；空空间也必须返回。
- 产品空间选择＋工作集有效范围＋分类投影定位，查询只呈现已准备可用内容。
- 当前范围／指定 snapshot 查询，SHARED 当前语义与 UNSHARED 固定内容分开。
- 本地内容、删除证据、固定来源的读取优先级；索引延迟不可导致回源复活。
- 历史端口、单版次对象 revision=1 的历史内容读取、附件保留和历史不可达结果。
- 按类型及来源批量读取、分页固定范围、避免逐条源查询、过滤与权限。

**完成标准**：对查询结果给出可信版本依据，读取不生成物理副本。

### D05 命令、事件与实例化

- ProductSpaceCreated、TrackerCreated、绑定完成与空间初始化完成的载荷、接收方、冻结集合及逐项幂等依据。
- 业务写事件和 ItemInstantiated 的精确载荷、生产方、消费者、处理结果。
- 全派生链候选与有效依赖匹配，事件旧内容不匹配切点时的输入获取。
- 目标业务聚合提交、索引独立确认、乱序／重复／删除竞争的行为表。
- 原生创建与派生创建的两个索引入口；事件失败查询及对账责任。

**完成标准**：07 的全部验收能映射为契约测试；不设计框架事务算法。

### D06 工作集生命周期与任务编排

- 产品空间创建事件、默认空间绑定、分类集合冻结、逐分类投影、Tracker绑定及空间完成；不使用循环大事务。
- 创建／拓展支持空空间，移除最后一个Tracker保留空间；完整替换按snapshot切换两层绑定，不复制产品空间。
- create／extend／replace 共用步骤和区别；任务输入冻结、幂等与结果封闭。
- 平台预置默认根的加载校验；重复纳入的准备占用、同请求重试、删除后新身份重新纳入。
- bind／unbind／archive／delete／恢复的独立场景；重挂首期支持或明确排除。
- 并发矩阵：业务写、拓展、替换、合并、子工作集创建、删除、共享对象变化。
- 准入、取消和发布竞争、单聚合提交边界、资源保留与异步清理。
- 前端状态：受理成功、可读、可写、关系恢复中、失败可重试、已完成。

**完成标准**：成功、失败、重启、取消、迟到事件各有明确终点；SHARED 不被误清理。

### D07 引用关联与 Compare／Merge 衔接

- 引用专项与拓展恢复统一，逐关系事务，缺端点关联意图来源明确。
- 合并执行通过事件收敛，Round 与 Checkpoint 独立提交，保留真实最终内容证据。
- Checkpoint 投影落后时的读取与重试，旧确认失效，恢复内容后不沿用旧 equal。
- 关系版本、钉版、签出与取消、传播可先限定支持范围，但不能留隐含同步大事务。

**完成标准**：业务应用、确认、轮次收尾与关系恢复均可独立恢复；领域规则、时序和测试一致。

### D08 仓储与持久化映射

- 每个根的 load/save/create 语义，加载完整性、预期版本和并发失败结果。
- 私有索引仓储、业务类型仓储、查询投影分离；一聚合不要求一张表。
- 产品空间仓储、Tracker 分类及空间引用、生命周期归属字段；分类元模型通过外部契约访问，不重建权威分类表。
- 空间绑定与Tracker绑定由WorkingSet仓储统一维护；物理分表不建立独立领域仓储。
- 原始空间／分类唯一创建和子工作集有效范围唯一投影的持久化防线，覆盖并发与准备态占用。
- 唯一约束、历史记录、任务映射、事件处理证据与必要查询索引。
- 虚拟条目没有本地业务行时的合法存在性；关系外键不能强制先实例化。
- 图关系数量、聚合所有权与物理关联分别说明，禁止以 FK 自动推断组合关系。
- ID 值对象映射标量列，不要求单独 ID 表或仓储；禁止映射跨聚合级联加载／级联保存。读取其他聚合由应用层或查询模型显式完成。

**完成标准**：依据已经确定的领域键制定表结构，不从旧表名称反推模型。

### D09 验证、运维接入与演进

- 聚合单元测试、公共 SPI 契约测试、事件交错测试、查询一致性测试。
- 故障点覆盖：空间已建／Tracker部分完成、Tracker已建／默认绑定未完成、源已提交／目标未建、目标已建／索引未确认、范围已发布／回执丢失。
- 两个产品空间使用同一分类集合，分别产生独立 Tracker；重复事件不新增投影；共享生命周期只归默认根。
- 子工作集移除全部Tracker后空间仍可查询；错误空间Tracker拒绝绑定；空空间纳入、快照、替换与显式移出均可验证。
- 对账输入、人工重试与审计权限；同步延迟、失败目标数及历史保留积压。
- 性能预算：成员数量、层级深度、分叉宽度、事件大小、历史读取量、批量分页。
- 若需旧系统接入，另设迁移设计，不让兼容存储决定 V4 聚合边界。

**完成标准**：有可重复的验收证据，不仅是“正常流程跑通”。

## 7. 落地顺序与评审关口

| 阶段 | 工作 | 进入下一阶段条件 |
|---|---|---|
| A：规则冻结 | D01、D02；关闭身份、范围版本与生命周期缺口 | 状态与不变量无冲突，待决业务明确支持／拒绝 |
| B：空间与最小业务接入 | D03、D04及D06初始化；预置根／分类→空间→Tracker→默认绑定→Requirement | 两空间同分类投影独立，公共依赖边界成立，Part 不受影响 |
| C：事件实例化纵向闭环 | D05；一条三层、多分叉派生链 | 源写、目标内容、索引确认三个阶段可独立失败与恢复 |
| D：工作集任务 | D06；创建→拓展→历史替换→解绑清理 | 范围发布、取消和并发守卫验证通过 |
| E：专项集成 | D07；引用恢复与合并确认 | 无跨聚合提交残留，投影滞后不导致重复业务操作 |
| F：完整持久化及验收 | 完善 D08／D09，补生命周期场景 | 所有首期能力有可执行契约与故障验收 |

D08 的最小仓储契约应随 B／C 进入样例，不必等 E 才设计；完整优化与表结构收敛放在规则稳定后。可以先实现最小纵向验证，不宜同时生成所有模型骨架后再补关键规则。

每次评审提交一个可核对的包：场景、状态表、聚合类图、接口签名、事件表、成功与失败时序、仓储合同、验收矩阵。仅新增类名、属性和服务层次不算闭环。

## 8. 详细设计交付清单

每项能力提交以下内容：

1. **场景与边界**：参与者、前置条件、输入、结果、不支持的情况。
2. **模型**：聚合根、内部实体、值对象、字段含义、关联方向与数量。
3. **行为合同**：方法签名、守卫、状态转换、幂等及失败结果。
4. **事件合同**：生产方、消费者、身份与版本、输入依据、成功和拒绝结果。
5. **协作流程**：正常、冲突、部分成功、取消、重试及迟到事件时序。
6. **存储合同**：仓储方法、并发控制、唯一性、历史读取与保留条件。
7. **查询合同**：可见范围、部分同步状态、批量读取、分页及权限。
8. **验收矩阵**：每条不变量至少对应一个正常场景和一个拒绝／竞争场景。

首个可执行样例覆盖：预置默认根与分类 → 创建产品空间 → 逐分类 Tracker 投影 → 默认绑定 → Requirement 原生创建 → 索引同步 → 三层派生 → 虚拟查询 → 源修改 → 多目标实例化 → 索引确认。增加第二产品空间验证同分类多投影，再验证共享生命周期的默认根归属。随后接入 Bug 和非受管 Part，验证业务扩展与隔离，再完成工作集任务、引用恢复和合并确认。

详细设计完成的判断是：实现者能够据此确定每个操作修改哪个聚合、发布什么事实、何时对用户可见，以及失败后从哪里继续。
