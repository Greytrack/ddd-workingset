# 领域范围与设计目标

> 新版本领域设计，作为 DDD 实现与验收依据。

## 1. 业务目标

工作集支持并行开发与多产品线管控：创建时基于索引建立关系，业务内容通过 COW 独立演化；保留对上游变化的感知，避免内部变化传播到外部。

## 2. 领域边界

| 能力 | 本设计的责任 |
|---|---|
| 引用 | Reference 独立聚合的身份、版次、有效性、钉版与修复 |
| 关联 | Association 独立聚合的类型、规则、传播能力与上下游取舍 |
| 工作集协作 | 根据 Binding、Tracker 与 Item 索引建立和解析关系 |
| 合并协作 | 应用明确引用决定，成功提交后通过事件修复悬空引用 |

工作集生命周期、Item 内容与 COW 闭包、版本管理、权限判定分别由对应领域提供；本设计使用其契约，不重复定义这些聚合。

## 3. 核心场景

| 场景 | 领域结果 |
|---|---|
| 创建工作集 | 保存上游引用与两侧齐全的上游关联；丢弃下游关系 |
| 拓展工作集 | 纳入 Tracker 或 Item，发布事件修复已有有效悬空引用 |
| 分支合并 | 根据明确决定修改引用；成功组发布修复事件 |
| 签出 / 取消签出 | 追加或撤销引用版次记录，不复制同一引用聚合 |
| 查询 / Diff | 读取有效关系、解析目标与展示差异，不写修复结果 |

## 4. 必须保持的不变量

1. Reference、Association 独立于业务对象、Tracker、WorkingSet 和 MergeRound 聚合。
2. 悬空引用已落库且有效，左侧存在、右侧为空，逻辑目标仍可识别。
3. 修复只补齐同一引用右侧，不改变身份、版次有效性、怀疑标记或合并确认。
4. 下游引用不复制；下游关联永久丢弃、不恢复，悬空关联不落库。
5. 关系行建立不要求复制 Item 内容，COW 不重复建立关系。
6. 跨聚合修复通过可靠事件最终一致，业务提交与修复完成分别报告。
