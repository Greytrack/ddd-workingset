# 应用协作与验收

规则见 [02](./02-domain-design.md)，事件协议见 [05](./05-event-driven-repair.md)，合并边界见 [09 §8.5](../09-merge-domain-design.md#reference-diff-merge-repair)。

## 1. 接口分工

| 入口 / 接缝 | 职责 |
|---|---|
| ReferenceCommandService / AssociationCommandService | 应用写用例与事务边界；Guard 断言 → 工厂 / 聚合行为 → 各自 Repository |
| ReferenceService | 批量签出 / 取消签出；取消须装载工作版次全部参与记录，含 INVALIDATED |
| ReferenceRepository | save / remove / loadEffective / loadRevisionParticipants；分别支持有效引用与指定版次全部参与记录的装载 |
| ReferenceProvider | findUpstream / findDownstream / existsByTarget，按引用方版次求有效性 |
| AssociationRepository / Provider | 前者供领域装载、守卫与保存，后者供应用清单筛选排序 |
| QueryService | 唯一回显拼装点，批量调用 LiteBusinessObjectService，避免逐对象查询 |

普通清单不分页，后台构建分批。可缺目标概要，不可丢失有效引用；历史概要按所钉版次读取。无权结果脱敏，不等于不存在。

## 2. 用例衔接

| 场景 | 关键顺序 |
|---|---|
| 创建 | 冻结来源 → Binding / 索引 → 保存上游引用与合法上游关联 → 发布；内容 COW |
| 拓展 | 发布新增 Binding / Item 及事件 → 独立消费，修复旧引用 |
| Diff | 读取两侧有效 Reference 并解析；区分逻辑差异和悬空状态，只读、不发事件 |
| Merge | 复核选择 → 合法记录 / 属性 / 引用操作 → 数据、结果、确认和 Outbox 同组提交 → 事件修复 |

引用属性或钉版不同是不同引用，LocalId 不同本身不是逻辑差异。ACCEPT 换目标走失效旧引用＋新增；KEEP_TARGET / DEFER 不擅自补目标。比较依据包含关系版本、有效版次、目标选择、Binding / 索引及生命周期；版次记录未准备完整时不进入比较。

## 3. 版次与持久化

关系行在创建 / 拓展时独立落库，COW 不重复建行；同批重试用构建映射防重。签出只追加记录，取消签出撤销工作版次记录，聚合空才删除。

若版次记录异步维护，需准备状态与因果顺序保护：完成前禁止相关编辑 / Diff / Merge，取消后迟到签出不能补回被丢弃版次。它不同于索引已提交、悬空修复尚在消费的最终一致状态。

## 4. 验收清单

| 检查点 | 关键断言 |
|---|---|
| 聚合与方向 | 各关系独立仓储；工厂不导致组合；上下游取舍符合02 |
| 签出 / 取消 | ID不变，每版次最多一条；取消含失效记录，历史正确恢复 |
| 换目标 / 钉版 | 失效旧引用＋新增；无可验证历史版本不降级HEAD |
| 去重 | 引用按属性、目标、钉版区分；关联同源同目标不因类型不同重复 |
| 悬空落库 | 左侧非空、右侧NULL、记录有效；修复同ID补齐，不新增或失效 |
| 创建与COW | 索引先行、关系独立落库，内容不全拷贝；重复任务不重复建行 |
| 下游关联 | 无DB行、无待恢复清单；拓展、事件和COW均不恢复，原工作集关系不动 |
| 并发与传播 | 拒绝过期写入；修复不清怀疑、不自动确认、不跨族误传播 |

事件重投、乱序、半批失败及查询进度的验收集中见 [05](./05-event-driven-repair.md#6-验收)，不在此重复。

## 5. 待决策事项

| 决策 | 当前设计与待确认边界 |
|---|---|
| 关联类型可编辑性 | 暂按类型可编辑、端点不可编辑；需业务确认 |
| 版次事件顺序与准备状态 | 明确同步协调或异步门禁方案 |
| 钉版历史对应、元数据去重作用域 | 由版次 / 元数据能力提供事实 |
| 传播写接口、跨边界隔离、钉版HEAD提示 | 结合关系类型策略闭合 |

上述验收为新版本实现的测试计划，不代表已通过。
